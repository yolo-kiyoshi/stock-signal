# Light継続での財務・保有リスク分析

2026年9月6日実装。J-Quantsの契約はLightのまま維持する。定量分析情報を提供し、注文や投資助言は行わない。追加ルールによる運用成績改善は未検証であり、確率に変換しない。

## 4段階の確認

| 段階 | 実装 | 欠損時 |
|---|---|---|
| 企業を検討できるか | 売上・営業利益・純利益・EPSの前年同期比、利益率変化、開示ROE・自己資本比率、営業CF・現金、会社予想PER・PBR | 中長期の購入候補を保留 |
| 今が買い場か | 既存のスイング・中長期テクニカル | 既存の不足判定 |
| イベント・環境を確認したか | 同年度の営業利益会社予想の下方修正、既存の決算予定・市場環境 | 本文未確認と明示。無事故とはみなさない |
| 資金上何株までか | 現金・許容損失・銘柄集中・業種集中の最小上限、コスト、売買単位 | 株数を未算出。設定済みで評価不能なら候補を保留 |

財務は方向スコアに加算しない。中長期は数値確認済みの場合だけテクニカルの購入候補を維持する。スイングでは財務未取得だけでは方向や候補を変えず、直近30日以内の営業利益予想の下方修正を独立した保留理由にする。開示本文を読んだことや企業価値の適正価格を算定したことは意味しない。

## 財務データと時点

[公式の財務サマリー仕様](https://jpx-jquants.com/ja/spec/fin-summary)に基づき、`MarketDataProvider.fetch_financial_summaries`の背後で銘柄指定と通常ページングを使用する。Premium専用の差分カーソルや有料アドオンは使わない。

- `financial_disclosures`に銘柄・取得元・開示番号をキーとして追記する。開示日・時刻、会計期間、会社予想の年度と初回取得日時を保存する。同じ開示番号の内容を後日上書きしない。別番号の訂正は別レコードになる。
- 日次バッチはウォッチ・保有銘柄を同期する。財務の失敗は`@FINS:証券コード`として独立記録し、株価取得を止めない。
- 全市場では先に両期間のテクニカルを評価し、購入条件を通過した銘柄の財務だけを追加同期する。両期間・ウォッチ・保有との重複取得を避ける。取得失敗・不足は画面で「財務確認待ち」と区別し、中長期の未確認候補は通過させない。同期失敗はバッチ結果にも残す。
- 現在画面の財務基準日は当日、株価基準日は最新日足であり、別々に表示する。財務開示当日の数値は利用せず、本日開示がある場合は内容確認まで購入候補を保留する保守的な日次ルール。休日に前営業日の開示を見落とさないよう、財務基準日を古い株価日に戻さない。
- 150日超の開示は古いものとして保留。同期自体も4日超未更新・失敗・未実行を区別する。
- 累計値同士で比較する。同じ書類種別・会計期間区分、前年の終了日との差350〜380日、期間長の差7日以内を必要とする。前年値が0以下の成長率は未算出。
- 配当のみの修正で業績予想を消さない。同年度・同じ連結区分の下方修正を30日間保持し、その後の変更なしの開示で警告を消さない。予想PERには最も近い有効年度の最新予想を使う。
- 四半期EPSを4倍しない。PERは有効な年度の会社予想EPSが正の場合だけ計算する。会社予想と市場コンセンサスは区別する。
- 株価は実価格を使用する。採用開示後に分割等がある場合、PER・PBR・EPS成長率を未算出とする。一株指標の過年度修正が保証されるわけではない。
- 赤字、営業利益の前年同期比10%超減少、会社予想PER40倍超は確認水準とする。40倍は業種横断の暫定値で、適正価格や学習済み閾値ではない。連結範囲変更・修正再表示は単純比較の再確認対象とする。
- ROEは開示値を表示する。四半期利益から独自に年率換算しない。欠損は0で埋めない。

## 資金・集中度

画面の「資金・許容損失・上限比率を設定」に、運用総資産、現金残高、1回の許容損失、銘柄上限比率、業種上限比率、片道コストbp、対象銘柄の売買単位を登録する。総資産は保有株評価額を含む。同じポートフォリオ範囲で入力する。架空の資金や既定の許容損失額は入力しない。

```text
片道コスト率 = cost_bps / 10000
購入単価 = 実価格 × (1 + 片道コスト率)
想定損失/株 = 実価格 - 実価格基準の損切り目安
             + (実価格 + 損切り目安) × 片道コスト率
株数上限 = min(現金 / 購入単価,
              許容損失 / 想定損失,
              (総資産 × 銘柄上限 - 既存銘柄評価額) / 購入単価,
              (総資産 × 業種上限 - 既存業種評価額) / 購入単価)
```

負の余力は0とし、指定単位で切り下げる。購入候補以外は0株。設定・価格・損切り目安・業種・保有評価額の不足は未算出にする。現金と登録保有評価額の合計が入力総資産を超えた場合も未算出。4暦日超古い価格で株数を出さない。この暦日制限は大型連休に保守的に働く。

対TOPIXベータと保有銘柄相関は調整済み価格から算出。リターンの開始日と終了日の両方が一致する直近最大60組、最低40組を要求する。分散0や不足では未算出。相関0.8以上を注意表示するが、検証していない株数倍率には変換しない。相関やストップは将来損失を保証しない。

資金設定・保有変更時、旧スナップショットの購入候補を様子見へ戻す。銘柄詳細は毎回再計算し、市場一覧は次の日次スクリーニングで更新する。画面の資金設定は一つのポートフォリオ用であり、保有期間は現在のスイング／中長期選択に対応する。

## 既存実装の点検と修正

1. 許容損失だけの株数計算では現金以上を表示し得た。サーバー側の資金・集中制約へ変更した。
2. 複数銘柄分析で最新銘柄の日付を他の銘柄へ流用していた。市場環境の参照日を銘柄ごとに解決する。
3. 市場環境の鮮度判定が未来日付を除外していなかった。東京日付との差が0〜4日の観測だけを使用する。
4. 過去検証で個別株の翌日始値とTOPIXの同日終値を比較していた。両者の翌日始値を起点に揃えた。
5. 保有データの読み取りは分析要求内で共有し、銘柄ごとの重複読み取りを減らした。

## 検証と拡張の扱い

既存の過去検証はテクニカル検証であり、この財務・現時点の保有制約を混ぜない。後から取得した訂正財務の初回取得日時を過去へ遡らせることも行わない。日次分析スナップショットに追加判定を保存し、今後の前向き比較に備える。

次の比較では5日・20日後の対TOPIX超過、上位3銘柄、最大含み損益、損切り到達、候補数、売買コスト、急落回避、業種・時期別の安定性を使う。時系列の無作為分割は行わない。今回の追加ルールがこれらの成績を改善したという結論はまだ出さない。
