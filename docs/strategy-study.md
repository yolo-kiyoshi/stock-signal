# 固定条件の時系列評価仕様

`strategy-study`は、明示された銘柄・評価期間・エンジン版・コストで保存日足を評価し、
ブレイク追随、スイング押し目反発、中長期押し目の経路別にJSONを出力する。
固定ルールのイベント評価であり、モデルの学習や閾値の最適化は行わない。
通常の購入判定・DB・保有情報は更新せず、外部市場データを取得しない。

## 評価条件

| 項目 | 入力契約 |
|---|---|
| `symbols` | 重複しない4文字の証券コード。最新の流動性順位から自動選択しない |
| `provider` | `jquants` |
| `horizons` | 5・20営業日の一方または両方。重複不可 |
| `windows` | `name`・`start`・`end`。日付はYYYY-MM-DD、両端を含む。時間順・重複なし |
| `cost_bps` | 片道コスト。0以上10000未満の有限数 |
| `engine_version` | 実行中の分析エンジン版と完全一致が必要 |
| `selection_notes` | 銘柄・期間の選定理由と、既に結果を確認した範囲の記録 |

全項目を必須とし、未知の項目も拒否する。期間の自動延長や銘柄の暗黙の追加は行わない。
条件の正規化後のSHA-256、評価処理版、エンジン版、入力日足のSHA-256を結果に含める。
同じ条件でも保存日足の訂正・追加で入力が変わる場合がある。
結果ファイルの上書きは拒否する。

## 時点とイベント

- 各判定には判定日以前の個別株・TOPIX日足だけを渡す。鮮度の基準日も判定日に合わせる。
- 判定前の助走期間の価格は参照するが、そのリターンを評価期間の成績に含めない。
- 評価期間の終端より後の日足は参照しない。5・20営業日後の実績が終端を超えるか、保存日足が足りない場合は未成熟として収益集計から除外する。
- 連続する同じ経路の購入候補は初日だけをイベントとする。期間開始直前の日足も判定し、継続中の候補を初日に新規計上しない。
- ブレイクから押し目など、採用経路が変わった場合は別イベントとする。未成熟かどうかを候補継続の判断に使わない。
- 候補日数、イベント数、成熟済みイベント数は別々に出力する。
- 銘柄・期間・分析日数ごとに評価日数と不足状態を出力する。データなしを「候補0件で検証完了」と同一視しない。

## 金融計算と集計

判定翌営業日の始値で購入し、判定から5または20番目の後続取引日の終値で売却したと仮定する。
片道コスト率を`c = cost_bps / 10000`として、次を計算する。

```text
コスト控除前リターン = (終了終値 / 開始始値 - 1) × 100
コスト控除後リターン = (終了終値 × (1 - c) / (開始始値 × (1 + c)) - 1) × 100
TOPIX超過 = 個別株のコスト控除後リターン - 同期間TOPIXリターン
```

TOPIXは同じ開始日の始値と終了日の終値で比較し、TOPIX側のコストは控除しない。
いずれかの日付が欠ける場合、超過リターンは未算出とし、比較できた件数を併記する。
MFE・MAE、損切り・目標到達は期間全体の高安による診断であり、途中決済の損益ではない。

期間・分析日数・経路別に、コスト前後の平均、コスト後の中央値、正のリターンの比率、
TOPIX超過の平均、MFE・MAEの平均、損切り到達比率を出力する。
標本がない指標はnullとし、0や架空の確率を補完しない。
正のリターン比率は評価対象の実績割合であり、将来の上昇確率ではない。

## 未解決事項

- 評価期間の指定だけでは、条件決定に未使用だった期間であることを証明できない。条件の事前登録と前向きな収集は別途必要。
- 学習期間での調整と後続期間の評価を繰り返す正式なウォークフォワード学習は未実装。
- 経路別の集計は対象事例が異なるため、経路を変更した場合の改善を示す対照実験ではない。
- 財務・資金・過去の決算予定・寄り付き前市場環境は対象外。最終購入区分の収益性は評価しない。
- 現在保存された遡及調整済み系列を用いる。当時の配信内容、上場廃止銘柄を含む母集団、銘柄選択バイアスの解消は保証しない。
- 保有期間が重なるイベントを許容する。独立標本、資金制約込みの運用成績、ポートフォリオの最大ドローダウンとして扱わない。
- 入力ハッシュは同一性の確認用であり、原データの保存やDB更新の排他制御は行わない。
