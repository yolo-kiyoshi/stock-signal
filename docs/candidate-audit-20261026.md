# 購入候補の少なさに関する調査（2026年10月26日）

調査対象はローカルPostgreSQL、稼働中API、判定エンジン2.17.0。株価基準日は2026年10月23日。
以下は分析システムの監査であり、銘柄の購入推奨や投資助言ではない。

## 結論

「両期間とも0件」は正常な判定結果だけではなかった。APIが古いコードを保持しており、
新しい版の保存済み分析を再分析待ちとして除外していた。API再起動により中長期1件の表示を復旧した。
スイング0件は現行ルールに沿うが、ルールが適切な厳しさであることや収益性を意味しない。

| 最新日の保存済み結果 | スイング・5営業日 | 中長期・20営業日 |
| --- | ---: | ---: |
| 分析件数 | 3,655 | 3,649 |
| 購入候補 | 0 | 1 |
| 様子見 | 1,764 | 1,861 |
| 新規購入回避 | 1,891 | 1,787 |
| テクニカル段階の購入候補 | 0 | 2 |

中長期のテクニカル通過2件のうち1件は追加の確認で保留され、最終候補は3986のみ。
この件数は当日のDBに対する結果であり、毎日の候補数や将来の成績を保証しない。

## 1. 表示上の問題：APIのコード更新が反映されていなかった

- DBの最新分析は全て2.17.0。3986の日足と分析日はともに10月23日で、調査日は3暦日後。
- 再起動前のAPIは両期間とも購入候補0件を返し、通常一覧では2.17.0の結果を「再分析待ち」と表示した。
- 同じコンテナ・DBに対して、新しいPythonプロセスで `list_market_candidates` を実行すると3986が候補になった。
- APIは10月21日から継続稼働しており、その後にコード変更があった。Composeの起動設定には自動リロードがない。
- `docker compose restart api` 後、同一APIでスイング0件、中長期3986の1件を確認した。

判定条件を緩和せずに復旧した。ソースのマウントだけではPythonプロセス内のコードは更新されない。
再発防止には、コード更新時のAPI再起動と、稼働中エンジン版・保存版を比較する運用確認が必要。
再分析待ちの説明文も、コード版不一致・日足更新・日数超過を区別すると原因が分かりやすい。

参照：`compose.yaml`、`database.py:list_market_candidates`。

## 2. スイング0件の直接要因：市場全体による一律保留

TOPIXの20営業日騰落率は−2.69%、市場点数は−13.4。
スイングでは20営業日騰落率がおおむね−2%を下回ると、ブレイク・押し目の両経路を保留する。
保存済みの市場条件除外診断では、他のテクニカル条件を満たす銘柄が5件あった。
これは市場条件だけを除いた仮定の結果であり、財務イベント・外部環境・保有制約まで通過する最終候補数ではない。

通常の最初の保留理由は、ブレイク経路の市場条件118件、押し目経路の市場条件9件。
この127件をそのまま「市場条件を外せば購入候補」と解釈してはいけない。
先に市場条件で返却するため、後段の出来高・価格位置・上位抵抗などに不合格でも同じ理由が表示される。
市場条件以外を再判定した結果が上記5件である。

さらにスイング押し目の形状判定だけでも、3,655件中2,838件がトレンド不成立、
436件が支持帯確認中、210件が上昇し過ぎ、158件が形状なし、12件が押し目形状成立、1件が未保存だった。
市場条件を外すだけで多数の候補が出る状態ではない。

一律保留には市場より強い銘柄を拾わない性質がある。相対力や市場回復を用いた別経路は検証候補だが、
今回の5件に合わせて−2%を変更する根拠はない。

参照：`analysis/decision.py:_decide`、`_decide_position_entry`、`analysis/engine.py`、`analysis/horizons.py`。

## 3. 中長期は実際には「中期上昇トレンド内の押し目」専用

中長期のTOPIX60営業日騰落率は−1.13%、市場点数−2.3で、市場保留には該当しない。
スイングと同じ理由で0件になっていたわけではない。

中長期経路では、20日線が60日線以上、60日線上向き、支持帯への直近3本内の接触・維持、
当日の反発、出来高または反発継続、相対力、損益比1.5以上などを組み合わせる。
最初の判定理由には下降パターン1,345件、トレンド不成立706件、反発待ち384件、
安値切り下げ191件、押し目から離れた状態107件、上値余地不足60件、短期相対力不足48件などがあった。
これらは順番に評価した最初の理由であり、独立条件ごとの全不合格件数ではない。

企業価値からの長期投資、業績回復、新高値への追随は独立した候補経路を持たない。
高値更新で過去の上値抵抗がなくなる場合も、目標を算出できず保留になる。
財務は主に候補を除外する追加条件であり、企業価値の割安さから新規候補を生成する仕組みではない。
「中長期全般の購入機会」を期待するなら、閾値調整より戦略範囲の不足が大きい。

参照：`analysis/position_entry.py`、`analysis/decision.py`、`research.py:enrich_analysis`。

## 4. 実装上の改善対象：終了した下降パターンが押し目評価を遮断

`LongOnlyDecisionPolicy._decide` は下降パターンの失敗・弱化・目標到達・期限切れでも
`WATCH` を返し、その後にある中長期押し目評価へ進まない。
「古い下降パターンだけでは判断しない」という理由文と、実際にはそのパターンだけで
現在の押し目経路を遮断する制御にずれがある。スイング押し目への切替にも下降パターン存在による制限がある。

中長期の該当707銘柄について、日足から押し目形状を再評価した。
559件がトレンド不成立、114件が支持帯確認中、14件が押し目形状成立、
14件が上昇し過ぎ、3件が形状なし、3件が支持帯接近だった。
押し目成立14件について終了済みパターンを取り除く仮定で判定しても、
全て損益比不足で保留となり、追加のテクニカル購入候補は0件だった。

今回の候補数に直接の増加効果はなかったが、終了済みパターンと新しいセットアップの独立性は改善対象。
修正時は、現在有効な下降・三尊候補・鮮度・決算・相対力・安全条件を維持する回帰検証が必要。

## 5. 別方向の不整合：購入判定と診断欄の上値抵抗が異なる

3986の現在値504円に対し、中長期の購入判定は目標528円、損益比1.80を使う。
一方、同じ分析結果の診断欄はより近い抵抗511円、損益比0.5254を示す。
原因は、中長期目標が抵抗帯を見つけるとそれを優先し、より近い過去高値との比較を省くこと。
診断計算は抵抗帯と過去高値の近い方を採用する。

これは「制約が厳し過ぎる」問題とは逆に、診断欄より楽観的な目標で購入候補にする不整合。
どの抵抗を戦略上の目標とするかを統一・明示する必要がある。
このため、表示復旧した1件についても、候補になったこと自体を判断の妥当性の保証として扱わない。

参照：`analysis/position_entry.py:_target_price`、`analysis/entry_diagnostics.py:nearest_resistance`。

## 対応と今後の優先順位

実施済み：API再起動、復旧後のHTTP応答確認、DB集計、終了済み下降パターン707銘柄の再評価。
判定ロジック・閾値・保存済み分析結果は変更していない。
Docker Compose内のPython 3.12で、関連する既存テスト57件が成功した。
対象は `test_swing_market_gate.py`、`test_candidate_consistency.py`、`test_decision_audit.py`、
`test_resistance_gate.py`、`test_support_and_pullback.py`。テスト成功は戦略の収益性の証明ではない。

1. 運用上の版ずれを防ぎ、再分析待ちの理由を分けて表示する。
2. 購入判定と診断の抵抗・損益比を統一し、終了した下降パターンによる経路遮断を整理する。
3. スイングの市場一律保留と、中長期の押し目以外の経路を別戦略として時系列検証する。
4. 候補が少ないことだけを理由に出来高・損益比などの閾値を一括緩和しない。

閾値の最適性、コスト控除後の成績、相場局面別の候補頻度は今回の単日監査では未検証。
検証では時系列を無作為分割せず、未使用期間・取引コスト・重複イベントを考慮する。
また、4暦日と7暦日が混在する鮮度条件は大型連休で候補を抑える可能性があるが、今回の直接原因ではない。
