# 未解決・残課題

現在の仕様に残る検証不足、データ制約、未実装機能を記載する。
以下は実装済み機能や性能保証を意味せず、優先順位・実装時期を確約するものではない。

## 分析ルールと検証

| 論点 | 現状・制約 | 必要な評価 |
|---|---|---|
| 閾値の妥当性 | RSI、ATR倍率、接触許容幅、R/R、現在足の終値位置などは固定ルール。最適値として未検証 | 同じ銘柄群・期間で条件を固定し、未使用の後続期間で比較する |
| 狭い損切りによる大きなR/R | 浅い損切りは比率を大きくするが、期待利益や到達確率を意味しない | 構造的水準とATR倍率別の水準で、損切り到達率、損失額、株数、コスト控除後損益を比較する |
| 形状と目標の意味 | 価格帯の分位点、近傍の日足本数、傾きの許容幅による検出は、独立した反転接触と同義ではない | 独立接触・形成全体の傾き・高値抵抗を用いる方式を比較する。幾何学的目標と期限内到達を分ける |
| TOPIX下落時の保留 | 市場条件で個別条件の通過銘柄も保留される。候補ゼロだけでは不具合と判断できない | 市場条件で保留した銘柄の識別表示と、相対力による例外の有効性を別々に評価する |
| スイング押し目反発 | ブレイク追随とは独立した経路があるが、収益性は未検証 | 経路別に候補数、TOPIX超過、最大逆行、損切り到達、コストを比較する |
| RSIダイバージェンス | 検出・反転監視の研究用実装はあるが、通常判定と画面には未接続 | 既存指標への追加情報、監視期限、反転待ちによる参入遅延、外れ値依存を未使用期間で評価する |
| 財務・保有制約を含む最終判定 | 過去当てはめはテクニカル評価であり、最終区分の成績ではない | 当時利用できた開示・市場環境・保有・資金の履歴を使う前向き比較が必要 |

正式な評価では、エンジン版、母集団、対象期間、取引コスト、判定条件を事前に固定する。
時系列を無作為分割せず、ウォークフォワード方式と未使用期間を使う。
5・20営業日の絶対リターンとTOPIX超過、件数、平均・中央値、最大逆行・最大順行、
損切り到達、コスト前後、銘柄・業種・相場局面別の安定性を確認する。
重複する保有期間のイベント平均を、独立した標本や資金制約込みの運用成績とみなさない。

単一銘柄や単日の結果を使った閾値調整、同じ標本での選択と評価、少数の大幅上昇への依存を避ける。
現在の流動性順位を過去へ適用する選択バイアスと、生存者バイアスの抑制も未完了である。
日足では同日のストップ・目標の到達順序、スプレッド、価格制限、売買停止を完全には再現できない。

## 財務と市場データ

- 決算予定は最新スナップショットであり、過去時点の公表済み予定を再現する履歴が不足している。
- 財務の単純比較は業種や会計上の差を十分に扱えない。営業利益が提供されない業種、連結範囲変更、修正再表示では確認待ちが残る。
- PERなどの業種横断の確認水準は暫定値であり、企業価値の適正価格ではない。過去のバリュエーション分位も未対応。
- 分割等の後の一株指標の調整は保証できない。欠損BPSを古いBPSで無条件に代用しない。
- 株価・財務の鮮度は暦日による制約を含み、大型連休では保守的に未算出・保留となり得る。
- EDINET本文・XBRL、TDnet本文、コンセンサス、追加のマクロ系列・発表カレンダーの統合は未実装。公表時刻、訂正履歴、利用条件と取得経路を定義する必要がある。
- 市場環境の警戒閾値は収益性を校正した値ではない。判断時刻に利用可能だった観測値による検証が必要。

## 保有情報とチャット分析

- 保有数量と平均取得価格は銘柄単位で合算する。NISA・特定口座別の売却分析は未対応。
- 保有基準日、数量、CSVの対象範囲は利用者による照合が必要。CSVにない銘柄を自動的に売却済みとは判定できない。
- レビュー保存時の出典形式・日時検証は、出典内容の正しさを保証しない。資料の実読と反対材料の確認が必要。
- 資料生成後の保有・仮説・資金変更は検出するが、同日の新しい外部開示による陳腐化を自動的に網羅できない。
- 資金設定は一つのポートフォリオを対象とする。相関は参考情報であり、検証済みの株数調整係数ではない。

## 認証と実行環境

- 操作監査とブラウザーE2E検証の自動化、公開環境での受け入れ検証が残る。
- ホスティング先・本番デプロイ構成は未確定。本人認証、内部API認証、DBの非公開化、秘密値の管理を公開環境でも維持する必要がある。
- Auth.jsの依存版について、外部公開前にセキュリティ更新と互換性を確認する必要がある。
- AI最終確認の同時実行制御はプロセス内Lockである。複数インスタンス化にはDBロックまたはジョブ管理が必要。
- 許可IDは複数指定できるが、利用者ごとの権限・データ分離、ネイティブアプリ向け認証は未対応。

## 予測モデルと注文機能

モデル用の保存領域はあるが、学習済みモデルによる確率出力、確率校正、正式な検証結果の管理は未完成である。
導入時には学習期間と評価期間の分離、基準日整合、必要履歴、データ品質、モデル承認、校正を確認する。
未生成の確率を推測値で埋めず、ルールスコアを確率へ読み替えない。

自動注文、ペーパートレード、証券会社接続、約定・残高照合は未実装である。
拡張する場合は分析・戦略判断・リスク検査・注文意図・執行・照合を分離し、
コスト控除後の期待収益、重複注文防止、資金・損失上限、停止条件、監査履歴を定義する必要がある。
AIの文章や現在の購入候補を直接発注条件として扱わない。
